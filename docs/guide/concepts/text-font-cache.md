# 文字度量、字体与缓存

布局结果只有在字符串、字号、样式、字体、字体版本与实际栅格比例一致时才能复用。缓存减少重复工作，不能修正度量与绘制条件不同造成的偏差。

## 一次文字请求

Renderer 根据字体名与样式解析字体配置，再度量或整形字符串。返回的宽高使用逻辑像素，内部字体按实际栅格字号工作。相同逻辑字号在不同 DPI 或超采样比例下可能有不同 hinting 结果，因此外部布局缓存还应包含 `textMeasurementScale()`。

`Fonts.revision()` 表示字体配置版本。重新注册或重载后，Renderer 在后续访问中使相关缓存失效；`renderer.reloadFonts()` 可立即释放其字体缓存。不要逐帧注册字体或清缓存。

## 测量会话是独立资源

`TextMeasureSession` 固定字符串、字体图、字号和比例，适合反复调用 `fit`、`measure` 和 `hitTest`。范围使用 UTF-8 字节，切开码点会被拒绝；`fit` 只保证码点安全，字素和语言断行仍由上层处理。

字体注册变化、切换族名或缓存淘汰不会修改存活会话的结果。会话因此也会保留旧字体资源，应在最后一次测量后关闭。Renderer 存活期间，会话的测量和关闭须在其所属线程执行；Renderer 关闭后继续测量会失败，重复清理安全。

## 缓存分层

| 层次 | 复用内容 | 观察或控制入口 |
|---|---|---|
| 字体发现与元数据 | 族名匹配、字体面、轴与文件元数据 | `Fonts.familyFaces`、`refreshSystemFonts`、`setMetadataCache` |
| 字体配置 | 主字体、显式后备和所选样式 | `resolveFont`、`reloadFonts`、`fontCacheStats` |
| 度量与整形 | 字符串范围、宽度与字形布局 | `textMeasureCount`、`textComputeCount`、`textShapeCount` |
| 字形图集 | 可重复绘制的栅格字形 | `glyphAtlasBytes`、`cachedGlyphs`、`glyphAtlasEvictions` |
| 整段文字纹理 | 斜体、旋转等路径的栅格结果 | `fontCacheStats` 中的纹理计数、字节及栅格化次数 |

字体配置分别拥有主字体及显式后备关系，避免族名之间互相改写后备链。自动 Emoji 后备是不可变叶子，同一 Renderer 内同实际字号可共享原生实例；普通文字不提前打开该字体。

单色整段纹理可跨 RGB 复用；包含彩色字形时 RGB 参与缓存键。透明度按次应用，彩色 Emoji 保留自身调色板。改变颜色不等同于重新打开字体。

## 当前实现的容量边界

以下是诊断资源成本时使用的实现预算，均有独立的统计口径，不代表进程总内存上限。

| 缓存 | 容量与边界 |
|---|---|
| 字体配置 | 每个 Renderer 最多缓存 24 个配置；彩色配置的 COLR／CPAL 表去重后按 64 MiB 预算淘汰 |
| 整段文字纹理 | 最多 256 个 GPU 纹理块、16 MiB；超预算单项临时绘制后释放 |
| 字形图集 | 16 MiB，按页淘汰 |
| 度量 | 默认缓存加最多 16 个命名字体缓存；每个最多 32 个字号桶，每桶两代、每代估算 64 KiB |
| 整形文本 | 每字体估算 512 KiB 布局预算 |
| 字体文件元数据 | 内存缓存最多 512 个文件、8 MiB；失败路径最多 512 项 |

本次请求、存活会话、FreeType 内部对象与驱动分配可能超出缓存统计。彩色字体预算允许单个超预算请求继续使用；不能据此推算应用的内存硬上限。图片纹理另有自己的缓存与预算。

超过 GPU 单张纹理上限的长文本先整段整形，再分块上传，采样边缘计入纹理预算。整段 CPU Surface 限 16M 像素（64 MiB RGBA），单字形图集槽含边缘不超过 2048 像素；超出支持范围会报错。

变量字体复用原文件的只读映射，仅为修改的字体表与尾部页分配私有数据，不按字重复制整份字体。连续改变坐标仍会创建轮廓和字形；交互预览应控制刷新频率或离散步长。

## 更新、失效与设备恢复

同名重新注册或 `Fonts.reload()` 使字体匹配与元数据重新按需解析，不立即全量扫描目录。可选持久缓存按文件大小与修改时间判断失效，损坏缓存可重建；应用负责准备可写父目录。

渲染重置使字形图集、整段纹理与场景目标失效并按需重建；字体与存活测量会话继续保留。应用自己的纹理和命令资源仍应遵循[资源所有权](resource-ownership.md)中的设备代数规则，不能假设所有设备丢失都可恢复。

## 如何判断缓存是否有效

重置计数后，在相同条件下重复度量。`textMeasureCount` 记录请求，`textComputeCount` 记录实际计算；请求增加而计算不重复增加说明复用生效。计数器不能代替耗时测量，也不能证明字形或对齐正确。

headless 使用确定性近似度量，适合状态、布局与边界测试。字体选择、字形覆盖、基线、DPI 和栅格输出必须用真实渲染器验证。实践见[排版文字与选择字体](../how-to/text-and-fonts.md)，字段含义见 [`FontCacheStats`](../../api/sdl/FontCacheStats.md)。
