# 文档与库验证说明

本页区分“链接存在”“代码可编译”“无窗口测试通过”和“真实窗口视觉正确”。任何一项都不能替代其余证据。

## 自动门禁

在仓库根目录执行：

```text
cjpm build
cjpm test
```

这两条命令验证当前库与测试套件。涉及公开示例时，还应进入受影响的 `examples/<name>` 目录执行 `cjpm build` / `cjpm test`；示例既是学习材料，也是公开 API 的端到端消费者。

项目采用 `cangjie-rules` 的 `cjcheck` 基线门禁。维护者应以仓库中的 `.cjcheck-baseline.json` 比较严格 Tier 2 结果，确保没有新增告警；不要为文档关联改动刷新或放宽基线。

Markdown 发布前至少检查 README 与 `docs/**/*.md` 的本地链接目标。`cangjie verify` 标记表示代码块应作为完整可编译程序维护；当前 SDL 仓库尚未提供统一的代码块抽取器，因此改动这类代码块时必须把它放入临时 cjpm 项目编译，不能仅凭阅读判定。

## 真实窗口边界

无窗口测试不能证明 SDL 动态库可加载、窗口可创建、字体包含目标字形、DPI 跨屏更新正确或 GPU 后端像素一致。修改窗口、事件、字体、纹理、渲染场景或 DPI 文档后，至少运行一个对应示例，并记录平台、Renderer driver、窗口逻辑/像素尺寸与可见结果。

多窗口功能应使用单一 `SdlEventPump`，验证关闭一个窗口不破坏另一个；渲染设备 reset 后应验证旧命令缓冲拒绝重放并能从 CPU 侧描述重建。文字视觉验收至少覆盖中文、拉丁、组合字符和 fallback 字体。

## 报告原则

报告实际执行的命令、退出码与失败边界，不把“构建通过”写成“视觉通过”。测试数量与性能数字以当前命令输出和机器报告为准，不在本页固化易过期计数。
