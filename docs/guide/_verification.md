# 文档验证说明

文档需要分别验证结构、编译、行为和视觉结果。构建通过不能证明窗口显示正确，无窗口测试也不能证明字体、DPI 或 GPU 输出正确。

## 自动检查

在仓库根目录执行：

```text
python .dev/cli.py check docs
python .dev/cli.py check snippets
python .dev/cli.py test examples
python .dev/cli.py test tools
cjpm build
cjpm test
```

这些命令依次检查：

- README、`.dev`、`docs` 与 `examples` 中的本地链接和标题锚点；
- 源码公开类型、函数、成员及重载是否都有 API 页面和索引入口，以及可调用签名中的参数、默认值和返回类型是否一致；
- README、示例、API 和指南中的完整仓颉程序能否在独立临时工程中编译；
- `calculator`、`thunder`、`contra` 三个公开示例能否独立构建；
- 文档工具自身、库源码和单元测试是否通过。

指南与各级 README 中的仓颉代码块必须包含包声明与 `main(): Unit`，并标记 `verify`。API 页面可以保留只展示签名的声明块；调用示例仍必须是完整程序。

项目还使用 `cangjie-rules` 的严格 Tier 2 基线。文档关联改动不应刷新或放宽 `.cjcheck-baseline.json`。

## 视觉验证

涉及窗口、字体、纹理、DPI 或渲染输出时，还要在目标桌面环境运行对应示例。至少记录平台、渲染驱动、窗口逻辑尺寸与像素尺寸，并确认：

- 窗口可创建、缩放和正常关闭；
- 中文、拉丁文字和所需字体回退可读；
- 几何边缘、裁剪、透明度与纹理显示正确；
- 截图尺寸和内容与当前画面一致。

多窗口场景应由一个 `SdlEventPump` 消费并路由事件。渲染设备重置后，应确认旧命令缓冲拒绝重放，应用能从普通数据重建资源。

## 报告原则

记录实际命令、退出码和验证边界。测试数量、运行时间和性能数据以当次输出为准，不在文档中固化易过期的数字。未执行视觉验证时，应明确写出“仅完成编译或无窗口验证”。
